# Native multi-instance host

The owned Java host drives **1–16 configured Minecraft Java 26.3 client realms in
one JVM**, on one owner render thread. The public launcher generates four slots
by default. The count limit is a configuration bound, not a GPU capacity claim.
See the [project README](../README.md), [runtime architecture](../docs/architecture.md)
and [third-party notices](../THIRD_PARTY.md) for the public support boundary.

## Fixed-version adaptation

The host requires JDK 25 and validates the unmodified client SHA-256
`4508d006323f24fa02876310c192d739af56516eb259000ac50f0909a68c9a2d`.
A narrow Java Class-File API transformation adapts **21 selected classes** in
memory. It replaces the original terminal `Minecraft.run()` call with native
registration and a host sentinel, then serially invokes the original
`runTick(true)` methods. Original construction, resources, networking, screens
and per-frame rendering remain native. No original JAR or asset is rewritten or
included in the source release.

Each realm loads mutable Minecraft, Blaze3D and RenderPearl classes through a
child-first loader. Parent-owned LWJGL JNI bindings have process lifetime; the
Vulkan loader is initialized once. Each realm still owns its own GPU device,
surface, swapchain, scene and textures. This is not a shared-scene renderer.

The actual `GpuDevice.getDeviceInfo()` backend/vendor and native SDL display
are checked at registration and during rendering. The configured logical slot
is matched to the actual SDL display through output bounds/origin, without
assuming stable enumeration order. Exact native window titles assign the corresponding
private compositor outputs; encoder capture views are a different ID namespace.
The host does not forge native minimized flags, dimensions or FPS counters.

## Build and start

Use the public launcher for verification, owned-host build, private media and
native process startup:

```sh
python3 scripts/multicraft.py prepare --config multicraft.json
python3 scripts/multicraft.py start --config multicraft.json
python3 scripts/multicraft.py status --config multicraft.json
```

A missing cache is an error unless `prepare --download` is explicit. An external
`minecraftCache` is verified read-only. Game files and build outputs remain
private. This flow does not start an existing Minecraft server or accept an EULA.

For a build-only developer command using an existing verified cache:

```sh
python3 scripts/build_m1_host.py --java-home "$JAVA_HOME" \
  --minecraft .runtime/minecraft/26.3 --build-dir .runtime/pool/build
```

This installs and downloads nothing. It compiles the owned sources into a
private JAR and records source/JAR hashes in `build.json`. Invoke the host with
the JAR and fixed game/library class path generated by the launcher rather than
constructing a partial class path by hand.

## Private control contract

The native HTTP control API binds only loopback. Every request requires
`Authorization: Bearer <contents of tokenFile>`. The token stays owner-only and
never reaches the browser. The public gateway separately authenticates players
and maps their selected identities to slots.

| Route | Behavior |
| --- | --- |
| `GET /state` | Owner-thread snapshot of every configured realm. |
| `POST /session/{id}/input` | Session-scoped event or bounded event batch. |
| `POST /session/{id}/command` | Controlled connect, disconnect, respawn, reload or terminal close action. |
| `GET /session/{id}/audio-state` | Owning audio epoch/device/context and sampler diagnostics. |
| `GET /session/{id}/audio?sinceFrame=N&maxFrames=4800&epoch=E` | Bounded native PCM range. |
| `POST /shutdown` | Gracefully close all configured native clients on the owner thread. |

Input/command mutations are fenced by runtime owner, connection epoch,
controller ownership and monotonic sequence. An old request must be rejected,
not retargeted to a newer client connection. A timed-out non-idempotent command
may already have executed; inspect state instead of blindly replaying it.

SDL3 scancodes/keycodes and modifier masks are used for keys. Absolute mouse
coordinates are native logical-window pixels; relative first-person deltas use
that same logical scale. Per-realm keyboard state and clipboard prevent the
physical process-global input channel from mixing players. Native mouse warping
and relative seat capture are suppressed because the browser owns capture.
Focus loss must release held input in the owning lease.

## Audio

`loopback-pcm` gives each realm a separate OpenAL Soft loopback device/context
and the original game sound engine at 48 kHz / stereo / s16le. Original OpenAL
calls bind thread-local context and LWJGL capabilities inside a reentrant
lifecycle scope, including asynchronous buffer cleanup. Resources carry their
audio epoch; late operations cannot reinterpret recycled IDs in a new context.

A bounded sampler retains two seconds of PCM history. Normal packets render
960 frames per 20 ms; explicit sample-index discontinuities let the browser
reset its scheduling clock. A long stall does not resume a stale backlog as
though it were current audio. The private range API reports epoch, start/end
frame, dropped frames and sample rate. Exactly four bytes represent one stereo
s16le sample frame. The public alpha relay uses uncompressed PCM, not Opus.

`disabled-probe` is a diagnostic silent mode. It cannot pass real game audio or
browser playback acceptance.

## Lifecycle compatibility policy

Ordinary disconnect closes the actual native network connection before dropping
the local level, and can reconnect in the same configured slot. Terminal close
is irreversible for that startup pool; recreating the slot needs a pool restart.

The current NVIDIA / Wayland integration uses the explicit `defer-native`
teardown plus `process-exit` SDL policy. Original per-session renderer/device,
surface, network and audio cleanup still runs. Exact instance/window destruction
calls are retired until all clients close; all registered instances/windows
must then actually be destroyed and the deferred queues become empty.

Only after successful client/audio/native cleanup, no remaining registered
handles and no live sampler does `process-exit` skip the final unsafe global
`SDL_Quit` and return through normal Java shutdown. Remaining process-level SDL
state is reclaimed by the OS. There is no `Runtime.halt`; failed or incomplete
cleanup refuses the clean success path. `sdlShutdown`, per-session cleanup and
`graphicsTeardown` snapshots expose the gate. This workaround does not establish
that native `SDL_Quit` itself is safe on this stack.

An abort during partial GPU initialization exposed an unresolved native
pipeline-compilation/cleanup race in the four-client test. Normal steady-state
cleanup success does not establish safety of that early-abort path. See the
[release validation record](../docs/release-validation.md) for retained failures
and the measured native/encoded FPS distinction.

The `standard`, `defer-window`, `defer-instance` and `native` policies remain
explicit diagnostic comparisons. Do not switch a live pool merely to hide or
retry a teardown crash. Retain crash logs and test both early/late close orders
plus actual full-process exit.

## Verification tools

- `multicraft.host.TransformCheck CLIENT.jar loopback-pcm` statically adapts and
  verifies the 21 selected classes. It creates no native client or connection.
- `multicraft.host.GraphicsCheck HOST_CONFIG.json` checks the original Vulkan
  bootstrap and an actual physical device without constructing full clients.
- `multicraft.host.FrameScheduleCheck` verifies the phase-accumulating
  per-slot due scheduler without constructing game clients. Live frame-counter
  differences remain necessary to establish actual requested rates.
- `multicraft.host.AudioCheck` creates synthetic independent loopback signals,
  checks their frequencies, epoch replacement, stale resource rejection and
  sampler/playhead recovery. It is not a real game-audio or speaker test.

Use the launcher-generated private class path and native flags to run these
checks. Their success does not replace a live N-client server connection,
original frames, menu/movement isolation, distinct browser identities and
actual audio playback. The [acceptance checklist](../docs/testing.md) keeps
those evidence categories separate.
